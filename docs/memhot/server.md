# Memhot 服务端

当前部署是Rust Axum + SQLite WAL单服务，由Nginx终止HTTPS。服务监听回环地址；检索经独立限额SearXNG，公开RSS与文献渠道作为补充。账号、文字、个人认知、研究与讨论按租户隔离。

## 运行配置

- `MEMHOT_DATA_DIR`：数据库、最小回执与运行配置目录，部署为`/var/lib/memhot`。
- `MEMHOT_BIND`：默认`127.0.0.1:8790`。
- `MEMHOT_PROVIDER_FILE`：运营方维护的权限受限模型配置，普通客户端无需输入密钥。
- `MEMHOT_SEARCH_URL`：回环SearXNG地址，当前为`http://127.0.0.1:8791`。
- `MEMHOT_PUBLIC_DAILY_CALL_LIMIT`：公共日报每日平台调用上限，当前20；0可暂停新增编排，不影响已有日报阅读。
- `MEMHOT_AGENT_NODE`：0.3 候选使用独立 Node 22.23.3 的绝对路径，不替换主机全局 Node。
- `MEMHOT_AGENT_SCRIPT`：0.3 候选为 `/opt/memhot/current/agent/src/main.mjs`；与 binary 通过同一 `current` 原子切换。

运行目录0700，配置与数据库0600，独立systemd用户及资源限制。模型密钥不进入仓库、响应或日志。新音频只在转写请求内存中处理，文字提交后确认；离线转写上传文字。不能把旧版audio目录行为当作新音频存储契约。

## 邀请与认领

新用户使用邮箱、密码、一次性邀请码。管理员用`memhot-server invite EMAIL`创建邀请；认领既有空间必须加`--user EXISTING_USER_ID`，不创建同名空间替代原资料。用户自行输入密码。CLI不会发送邮件；邀请期没有SMTP验证或真实充值。

`adminreset EMAIL`生成限时密码重置码，应先核实账号归属并经可信通道交付。`revoke USER_ID`撤销设备会话。旧pair端点属于既有公开API兼容义务，新UI已移除私有配对流程。

## 后台与故障

两个全局作业槽、同用户串行、有界检索、幂等模型回执与额度预占；调用不持有DB锁。未知付费结果不自动重复。租约fencing阻止晚到结果写回，删除墓碑阻止自动恢复用户已删除内容。新/变化的全部研究方向按用户时区夜间调度，不以首页列表上限截取。

原始文字按用户选择7/30/90/365天清理；到期或删除撤销依赖内容，人工独立偏好单独管理。公共编辑与抓取正文24小时后清除，公共日报通常30天但保留仍被引用版本。备份保留最近7次，主库清理不等于备份即时擦除。

## 0.3 候选的 Pi 运行时

日报、研究、讨论与翻译由官方 Pi SDK 1.1.0 会话执行。公开搜索和正文提取使用锁定的`pi-web-access` 0.38.0插件核心，由独立子进程执行，禁止自动摘要、浏览器、仓库克隆和媒体工具。Rust固定模型端点、保管密钥、校验工具范围并执行额度账本；Node子进程使用清空后的环境，只通过JSONL向Rust请求模型、工具及HTTP传输。私有续跑状态可能包含供应商要求的推理字段或签名，仅用于恢复会话，不进入客户端轨迹或日志，24小时后清理。

SDK源码、测试、精确锁文件与binary纳入发布清单。Linux依赖通过官方npm registry的完整性校验安装，禁用安装脚本，并以服务用户在资源受限的独立任务中运行测试。候选drop-in将Memhot内存软/硬上限设为256/384 MiB，CPU暂定100%（双核主机限一核），任务仍为64；Pi单子进程堆上限128 MiB。实际运行峰值需另以真实任务复核，测试峰值不能代替生产峰值。

候选准备不会切换正在运行的0.2服务或公开APK；只有完成模型质量、源码校验、数据库副本迁移及最终发布放行后才调用显式激活步骤。

当前部署步骤、实际版本哈希、资源与回滚流程见[ops README](../../ops/memhot/README.md)。数据库迁移后的回滚必须与相应备份配套，不能只换旧二进制。测试与实测局限见[0.2验收](acceptance-0.2.0.md)。
