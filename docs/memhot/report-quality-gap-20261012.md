# 日报内容差距：AIHOT 对照

2026-10-12，用户反馈当前报告比 AIHOT 少很多内容。此文记录调查，不代表以下功能已经补齐。对照版本：AIHOT `e36480d548aaa1c8461dc93b7b940559b6dd7099`，Memhot 0.2.0。

## 当前直接故障（RQ-01）

浏览器正在阅读的本地预览报告，主题是 AI 产品真实需求与付费意愿，但正文只有两份 arXiv 摘录，其中包含量子代数论文。报告自身注明生成时文字模型未配置。它属于收集到资料但未完成生成的结果，不应以正常日报的标题和阅读结构呈现。

`research.rs` 中缺少模型或编辑失败仍进入原始摘录分支，保存为 `kind=digest,status=partial`；`Reader.tsx` 对此仍显示“兴趣日报”。严格引用核验没有解决检索相关性，也没有解决“运行失败”和“已完成但仍有证据缺口”的区别。云端已完成的模型测试不能替代本地预览这一实际路径的验收。

验收方向：配置错误、编辑失败、没有相关材料、成功但证据有限应分别表达；失败不产出看似完成的日报。历史失败产物仍可查看来源和原因，不能被新生成状态掩盖。

## 采集与编排（RQ-02）

共享日报当前每个 feed 取4条、每个域名最多2条，总共取16个候选。之后排除取文失败、日期不明或过期材料，没有继续补位。编辑阶段最多10条，单份材料输入截为5000字符。私人订阅还存在搜索候选未经统一主题相关性检查的问题。

AIHOT 的开源流程持续采集与筛选、聚成事件、保存报道关系，再从积累的合格内容成刊。Memhot 当前一次性、小候选池的流程无法提供同等覆盖；单纯增加输出字数不能弥补缺失的材料。

验收方向：有界持续采集，先做主题和质量筛选，再去重与补位；保留可追溯的事件和原始来源关系。公开事件共享存一份，私人兴趣、推荐理由、讨论及认知仍按用户隔离。

## 阅读结构（RQ-03）

AIHOT 开源 `ReportPaper.tsx` 包含头版、导读、头条、栏目页、快讯、多源报道标记、跟进提示及往期导航。Memhot 目前只有概览、线性目录、摘要、编辑解读和来源链接；没有完整的栏目与事件阅读路径。它并非只差颜色、字号或卡片数量。

验收方向：概览 → 重点事件 → 分类栏目 → 快讯 → 资料与出处；读者可以由事件进入背景和进展，按期查阅，清楚区分摘要与已读取的正文。首屏仍保持简洁，将细节放入可展开的层次。

## 概览与持续阅读（RQ-04）

`editorial.rs::overview` 对100–180字符做硬校验；越界、某篇故事被淘汰或概览审核未通过，都会替换为前三个标题与固定文字。实际测试出现181字符被整体降级的情况。缺少基于最终保留事件修订概览的步骤。

目前也没有 AIHOT 的完整跨日事件进展、周月汇编、主题档案、全文相关搜索与阅读收藏体验。AIHOT 的运营信源名单和模型排行榜等线上专用功能不在该开源仓库，不能宣称可直接克隆获得。

验收方向：对最终事件生成并审核概览，失败须明确；持续阅读与事件积累分阶段实现，不用虚构概览或填充无关材料达到数量。

## 优先级

1. RQ-01：纠正失败产物及相关性问题，使用实际部署配置验证用户当前阅读路径。
2. RQ-02 + RQ-03：先形成足够相关的事件池，再构建完整日报阅读层次；评估复用 AIHOT 开源模块，避免重新实现已有成熟编辑流程。
3. RQ-04：概览修订、事件追踪、档案与阅读工具，分别以真实内容验收。

0.2.0 APK 已发布并核验，以上为已知后续改进，未包含在已验收基线中。
