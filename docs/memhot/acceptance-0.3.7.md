# 服务端 0.3.7：读取 PDF 与模型流格式修复

## 原因与范围

0.3.6 的正式研究已得到新的检索线索，但两次直接阅读都是 PDF，被文本阅读器拒绝；随后模型流中断，任务没有发布新报告。本版本补齐有界 PDF 阅读，并修复离线已复现的合法 SSE 格式误拒。不能据这些代码修改宣称历史 129 字节响应已被解释，或整套报告质量已经通过。

## 阅读边界

Rust 保持唯一网络出口，校验每次重定向、固定 DNS 解析地址并拒绝私有网络。公开 PDF 经内存传递给项目已有 unpdf；独立 Worker 限制 8 MiB 输入、40 页、17,500 字、15 秒和 64 MiB V8 堆，取消时终止。不执行文档脚本、不绕过密码或站点访问限制、不启用 OCR。

提取页数、总页数和截断状态通过独立 extraction 字段传递到工具、检查点、公共固定输入、研究审核和报告来源。正文只保留可核对原文，不能把限制说明拼入引文。已读取原文不等于整份 PDF 都读完；PDF 创建/修改时间不能冒充发表时间。

## 模型流边界

解析以 SSE 事件为单位，支持 BOM、CR/LF/CRLF 和多行 data。与 SDK 保持关键消费边界：坏 JSON 拒绝；OpenAI 遇 DONE 停止，后续结束原因无效；Anthropic 须有 message_delta 名称、类型与事件空行，不借用 OpenAI 的 EOF flush。错误事件及非 null error 仍拒绝；error:null 不误判。仍需要对应模型协议的终止原因，只有 DONE、截断响应或无效前导空格不会被放行。日志仅记录固定格式类别、字节数、JSON 事件数量和错误事件标志，不保留正文、提示词或提供商错误消息。

- 独立代码审查指出的截断透传与 SDK 解析差异已修复并补回归。`truncated=false` 只表示未触发提取预算，不保证扫描图片或复杂表格内容完整。

发布、服务器实网读取、真实报告内容验收分别记录；不能将格式单测或读取成功等同于新报告通过。历史失败任务和未知付费回执保持原样，不重置、不自动重放。
