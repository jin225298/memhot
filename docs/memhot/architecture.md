# Memhot：从日常对话延续思考

> 这是0.1阶段的架构背景与早期ADR。0.2的多话题、托管账户、可选本机ASR、存储和并发决策以[ADR 0004](ADR-0004-invitation-personal-research.md)为准。

日期：2026-10-12。状态：实现基线，交付状态另见 acceptance.md。
源代码基线：Memocat d54e0c346c9bfbc2d6245f4dcf31b7e062401f9e。

## 产品目标与首个验收场景

用户在日常聊天中提出不完整的想法，往往尚不知道缺少什么材料。Memhot保留原话和上下文，识别需要继续思考的问题与隐含假设，补充支持证据、反证和未知项，次日形成可追溯的研究材料，并支持围绕材料继续讨论。固定兴趣日报是另一条入口，不用热度代替个人问题。

核心场景：用户说“我在想这个行业的未来，但不知道有没有人买单”。系统不能仅推行业新闻；应区分购买者、付费动机、现有替代方案、市场证据与失败案例，标明哪些仍无证据。用户原话不是经过验证的事实，模型推断也不是用户已经认可的观点。

首批完整闭环：安卓持续采集/文本文件导入 → 耐久来源 → 思考线索 → 云端检索与研究 → 次日日报 → 来源阅读与AI讨论 → 反馈和清理。首要设备为一加Ace3 / Android16。Windows/macOS/iOS共享应用壳和服务协议，但各平台构建、签名、后台能力必须单独验证，不把架构支持写成已交付安装包。

## ADR-001：平台与服务选择

选择 React19 + Tauri2 + Rust，小而独立的新应用壳位于 apps/memhot。Android系统录音由Kotlin前台服务负责，音频不经过WebView，但Tauri进程退出仍可能结束服务，限制记录在MEMHOT-002。复用现有React/Markdown能力、Rust ASR协议及模型运行时；剥离ASR对桌面采集的类型依赖。

评估过 Flutter：跨平台UI成熟，但需要新增Dart运行栈并迁移既有Rust/React能力，首版没有足够收益。纯Kotlin适合安卓，但桌面/iOS需要重做UI。当前选择兼顾已有代码和四端演进；不直接移植桌面宠物、快捷键或完整voiceagent-host。

云端采用单个Rust Axum服务、SQLite WAL、耐久任务表和一个后台worker。既有服务器只有2vCPU/3.33GiB内存，审计时可用649MiB、磁盘剩余4.2GiB，因此不增加Postgres、Redis、Chromium或本地大模型。远程模型负责ASR/生成。仅公开Nginx HTTPS入口；服务监听127.0.0.1:8790，配置资源上限。现有服务先共存。

## 领域与依赖方向

| 边界 | 责任 | 不承担 |
| --- | --- | --- |
| Capture | 权限、音频分段、本地队列、中断恢复 | LLM、兴趣推断 |
| Sources | 输入校验、来源版本、角色/时间/原文位置 | 把AI文本变成用户事实 |
| Thoughts | 原始问题、假设、证据缺口、状态与反馈 | 伪造“用户想法” |
| Research | 来源收集、去重、证据、支持/反证、成稿 | 系统命令和任意网络访问 |
| Delivery | 按用户时区调度、持久化成刊、设备提醒去重 | 精确依赖移动端存活 |
| Discussion | 已选材料上下文、有限检索、会话历史 | 无授权读取其他用户资料 |
| Model adapters | ASR/文本供应商协议、能力与失败语义 | 业务事实和推荐决策 |

协议DTO、领域对象、数据库行与前端视图各自转换；校验在边界完成。所有新增/重构后的手写文件小于500行，自动生成文件另计。拒绝跨模块共享可变状态。已有超大模块不整包搬运；触及其职责时先提取所需小模块。内部旧路径直接替换，公开协议/迁移版本独立处理。

## 音频与电量

Android使用用户可见Activity启动microphone foreground service，通知始终可见并提供停止操作。默认16kHz/mono/PCM16，短帧检测、预卷、静音切段、最长30秒硬切。只把有声片段加入有上限的本地耐久队列；音频不经过JS帧事件。录音时不运行大模型、不刷新波形、不维持实时ASR长连接。批量联网与退避减少射频唤醒。

队列记录片段ID、采样参数、时间、哈希、attempt与状态；上传幂等，成功确认后删除片段。磁盘满、权限撤销、通话占用、系统回收有明确状态与恢复入口，禁止静默丢音频。重启/强制停止不能承诺自动恢复录音。电池优化引导针对一加/Android16，最终以真机8小时锁屏测试报告电量差、丢段和唤醒次数；模拟器不作为功耗证据。

服务端收到WAV先写入受保护暂存，再创建转写任务，确认完成后清理；失败有有限保留期。静音检测不是说话人识别。未确认的多人聊天保持身份未知，推断性兴趣带原话依据和撤销入口。用户可暂停、删除、不用于个性化。

## 个人思考与研究流程

来源文本 → 角色/来源校验 → 形成thought thread（问题、假设、缺失证据、原话） → 搜索计划 → 受限检索/抓取 → 去重 → 证据片段 → 研究包 → 引用校验 → 投递。

每条结论绑定source ID/URL、标题、作者或机构（若可得）、时间、检索时间及可定位片段。支持证据、反证和推测分开。来源不足时展示不足，不用模型常识冒充检索结果。网页中的指令当作资料，不执行。

兴趣流优先公开RSS/API和用户配置的来源；按用户兴趣选取，首版缓存按用户隔离。参考AIHOT的阶段化预筛、同事件去重、来源多样性与成刊；不照搬其站点/数据库，也不把其OpenAI兼容或retention实现当作全模型支持/正文清理。任何移植保留MIT归属。

默认用户时区Asia/Shanghai，次日08:00开始准备；允许修改。自动研究只选择用户当地日期早于当天的思考，手动研究不受此等待限制。任务键含user/date/kind，重复调度不会生成两份。离线设备再次打开时补收；Android本地通知和后台同步为投递提示，不能把OEM条件下的精确08:00通知当作保证。没有Google服务仍可拉取已生成日报。

## 模型与讨论

分别配置ASR和文字模型；研究、整理与讨论共用文字配置。文本协议明确区分OpenAI兼容Chat Completions、Anthropic Messages、Gemini generateContent；设置向导提供连接验证，未经真实验证的target不得显示“已验证”。已有Qwen/MiMo协议通过抽取模块复用；其他ASR只在完成协议测试后展示。

失败分鉴权、限流、超时、截断、输出非法和来源不足；总deadline、有限attempt与并发预算只有一个owner。没有模型配置时提供可浏览的原始资料和配置入口，不伪造AI文章。API key仅写入服务端受保护配置，响应永不返回；日志不记正文/密钥。

首版使用服务端可审计的研究流程与限额工具调用，工具为search、fetch_public_source、read_owned_evidence；不运行用户可控制的shell/SQL。不默认接入ClaudeCode/OpenCode等拥有广泛本机权限的编程CLI。点击文章进入携带article/report ID的会话；检索扩展仍通过相同授权与网络策略。将来确有跨工具任务时再评估SDK，避免先造通用agent平台。

## 认证、隔离和安全

设备通过一次性配对码换取高熵token；服务器仅持有token哈希，撤销后立即拒绝访问。每条私有表、查询、对象读取和任务都带服务端从token解析的user ID，不能信任请求自报身份；用两个用户验证所有读写路径。公开来源可以共享，私有原话/兴趣/研究/对话不可共享缓存。

输入限制类型、大小与解析深度；抓取仅HTTP(S)，拒绝本地/私有/元数据地址，重定向逐跳重新校验，限制时长、字节数和页面数量。客户端使用安全存储保存token；服务端模型秘密存于仅服务用户可读的SQLite，不进入Git或构建产物。

## 清理、并发与回滚

单进程SQLite WAL+busy_timeout，短事务；网络和模型调用不持数据库事务。任务具有租约、最大尝试次数、取消/失败终态，worker重启后可重取租约过期任务。采集、转写、成刊及投递均有幂等键。

原始音频转写确认后删除；失败音频最长24小时。抓取全文默认24小时后清理，仅留支撑已发布报告的有限证据片段、元数据和哈希。用户私有转写默认30天可调，删除来源时关联记忆失效/删除并取消未完成任务；已生成研究包标记其个人上下文已删除。报告与讨论保留到用户删除。清理须覆盖临时文件、任务payload及错误回执，日志不得保存正文。数据库备份采用有限轮替并说明删除传播窗口。

状态观测使用job/attempt ID、任务阶段与安全错误类别，系统服务记录启动/退出；不打印正文或密钥。部署以版本目录+systemd服务切换，数据库迁移先备份；回滚恢复对应二进制及兼容schema，破坏性迁移需备份恢复。

## 交付与验证顺序

1. 抽取audio-contracts/ASR依赖，独立应用壳、认证与输入闭环。
2. 原生录音、耐久上传、导入、思想形成与研究worker。
3. 日报、证据阅读、讨论、多模型向导与保留策略。
4. 本地行为/故障/隔离测试、安卓构建与模拟器，服务器TLS/健康检查与备份回滚。
5. 输出APK、SHA256、源码、配置说明和明确区分已验证/待真机验证的验收记录。

关键验收包括：断网后重传不重复；重复调度不重复成刊；两用户不能互读；无凭据/限流/网络失败可恢复；反证与未知可见；引用指向实际来源；删除及清理不破坏已保留证据；安卓锁屏录音、停止通知、权限撤销；不把未测试的平台宣称可安装。

## ADR-002：首版投递与时效边界

无GMS依赖，Android WorkManager每30分钟读取轻量`/api/v1/delivery`，而不是轮询包含私人全文的首页；服务按用户时区生成内容，设备只提供尽力送达的通知。精确推送需要未来针对实际安装渠道评估厂商推送，不用持续长连接增加电耗。

固定兴趣日报限定近7天有明确发布日期的新来源，按账号排除近期日报已经引用的规范化URL；没有可靠日期不冒称新闻。研究材料保留历史来源以支持纵向比较。RSS每轮最多3个并按日轮换，搜索2查询/全文6页/候选10条是当前小服务器的明确资源预算；高质量以引文核对、相关性和来源多样性约束，发现渠道的流行度不是权威性。

接口参数依据：[Crossref日期过滤](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/)、[Tavily日期范围](https://help.tavily.com/articles/3347142954-best-practices)。

## ADR-003：阅读关系与临时输入状态（0.1.1）

用户反馈原界面把输入、问题和材料混在一起。主导航改为今天（阅读收件箱）、思考（问题及关联）、记录（输入和原文）；设置降为头像入口。App持有当前问题、阅读分类与原文ID，读取由所属视图负责并随ID变化取消。进入阅读时固定当前分类，异步刷新不能改变返回位置。

未提交文字只在客户端内存中保留：记录与设置保留组件，讨论以已有上下文ID索引草稿。账号变化和清理数据时销毁；不建立跨设备草稿同步或落盘层，避免对尚未提交的私人内容引入额外存储与冲突语义。对应说明见应用内导入流程和用户指南。

## ADR-004：证据粒度与分析范围（0.1.1）

真实模型验收证明“一来源一个excerpt/stance”会覆盖同页多条结论。证据仍以公开来源为单位，但引文改为独立citation列表；每条带claim、逐字quote、fact/inference与立场，汇总excerpt保留所有已接受片段，混合立场归context。范围限制和模型推断不能满足实证反证要求；论文落地页的摘要不升级为全文。现有API字段保留语义，新字段为可选增量，无数据库迁移或双写旧实现。

会议身份未知是明确的导入选项，不因同一人名标签推断单一说话人。一次分析给主来源30000字符、相邻各1500字符，返回覆盖计数和是否完整；超界时保存全部原文，但说明只分析给定部分。暂不实现分块后多议题归并：单条线索是当前明确能力，不把其结果称为全议题覆盖。此限制跟踪MEMHOT-007，关闭条件为长会议跨块提取多个真实问题、去重关联与引文血缘的测试和实际验收。

讨论检索候选可供模型判断，回复给用户的sources只保留回答实际引用的已授权URL。匹配包含URL边界，避免将同前缀或查询参数嵌入当成引用；没有引用则清单为空。此决策提高展示准确性，不替代搜索相关性或模型事实核验。
