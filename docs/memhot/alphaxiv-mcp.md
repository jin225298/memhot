# alphaXiv 论文接入（服务端 0.3.4）

2026-10-13 用户授权接入个人 alphaXiv MCP，并提供凭据。唯一端点为 `https://api.alphaxiv.org/mcp/v1`，使用既有锁定的 `@earendil-works/pi-mcp@1.1.0`。官方说明：https://www.alphaxiv.org/docs/mcp 。实际 tools/list 返回 23 个工具；当前检索工具是 `discover_papers`，不能照搬旧文档的工具名称。

## 权限与配置

`MEMHOT_ALPHAXIV_FILE` 指向绝对路径的普通 0600 JSON 文件，仅含 `userId`、`apiKey`。禁止符号链接；没有配置则不暴露论文工具。它绑定已有邀请账号（或有效未认领邀请所指定的现有用户）的 tenant ID，不以邮箱字符串做运行时权限判断。文件和密钥不进入仓库、APK、模型上下文、子进程环境或普通日志。密钥只由 Rust 在已校验的固定 HTTPS 请求上注入敏感 Authorization 请求头。

个人研究、自定义兴趣日报、围绕报告的讨论可调用 `papers`；只有配置对应用户拥有权限。公共共享日报和其他用户不会看到或调用此工具，也不共享个人文献库的结果。此版本只配置一位授权所有者，不能把该密钥复制成全站共享配置。未来多账号接入应独立存储各用户授权，并将限流窗口从单个授权账号扩展为每凭据窗口。

公开 AI 日报仍使用 AIHOT、官方 RSS 和原文检索；私人文献库不会偷偷变成公共内容来源。

## 工作流

- `discover`：传递公开主题关键词，最多 6 个；每轮最多 2 次，固定低检索难度 2。关键词沿用用户或已有材料中的原词，不猜测缩写展开。明确请求近期内容时用 recency；只有用户指定时间范围才使用日期硬过滤。实时接口可能优先相关性返回旧论文，必须保留真实日期，旧文作为背景。
- `read`：只接受严格校验的 arXiv / alphaXiv 论文链接，统一为公开 arXiv PDF 地址，强制 `fullText: true`。不会把默认 AI intermediate report 当成论文原文。每轮最多 8 篇；一次取回最多 100,000 字符，每次给模型最多 18,000 字符；`nextOffset` 继续读取已缓存文本，不重复请求供应商。论文超过保留上限明确返回 truncated。来源 ID 随规范化 PDF URL 稳定，已知发表日期不改写为检索日期。
- `library`：每轮最多 1 次，仅当前用户的只读文献库，最多 30 个文件夹与 20 个不同公开论文。只支持具有可验证 arXiv 标识的公开论文；个人上传、列表截断明确标注不完整。此版本没有写入、移动、删除、关注或编辑权限。

搜索片段标为 `search_snippet`，不可直接支撑事实。只有原文读取后才能进入证据审核；文本不可信，不能作为工具指令。报告仍必须通过引文匹配和独立事实核对，不因来自论文而绕过验证。

## 调用、保留与故障

Rust 与 Pi MCP 通过受限 JSONL 通信。第二个真实 MCP 用例提取了共享 `mcp_transport.rs` / `mcp-readonly.mjs`；各来源仍保留自己的请求规则、结果解析、权限和缓存策略。只允许 initialize、initialized、最多两页 tools/list、一次精确 tools/call、取消和 DELETE 会话清理；无 OAuth、根目录发现、本地命令、资源加载或任意网络。工具除了固定允许名单还必须声明只读，不能声明破坏性操作。

AIHOT 和论文 MCP 共享一个独立子进程并发闸门。论文整次最多 60 秒（含等待），HTTP 45 秒，响应 2 MiB、单输出帧 512 KiB、累计通信 6.5 MiB、Node 堆 96 MiB；会话清理最多 900 毫秒。无自动重连或未知结果重试。429/503 遵守有界 Retry-After，最大一天。AIHOT 保持原来的 30 秒/15 秒和 512 KiB 响应限制。

alphaXiv 自身搜索/分析可能消耗该账号的 assistant 额度，不能假定免费无限调用。主机在发出请求前用 IMMEDIATE 事务原子检查用户 epoch、调用次数并写 `paper_receipt`。回执仅保留 run hash、操作名、时间，不含搜索词、密钥或文献库内容。原始结果及模型续接状态仍在私有 `agent_run` 中，24 小时后清理；无内容回执继续阻止过期/结果不明的同一请求自动重放。用户清空全部资料时一起删除。新研究需要新的 run ID；没有后台无限重试。

供应商故障作为可恢复的工具错误交还模型，可继续使用其他来源；权限、协议、持久化错误严格失败。配额上限同时覆盖已经发出但不确定的请求。取消/删除期间通过 epoch 和持久化事务阻止旧结果写回。

## 验证和运维

`alphaxiv_tests.rs`、`agent_papers_tests.rs`、`test/alphaxiv.test.mjs` 覆盖所有者隔离、公共拒绝、凭据不出主机、固定端点、只读元数据、原文强制、搜索日期、分页、调用次数及上下文清理后的永久回执。

`papers_live_qa` 使用全新隔离数据库，仅给测试钱包默认额度，不变更线上用户余额或自动恢复已有阻塞任务。它通过真正的 Pi agent、DeepSeek `deepseek-v4.1-flash`、Rust HTTP broker 和 alphaXiv 原文/文献库完成多轮调用，逐字（规范化空白）验证输出引文。原始回答与文献库结果保存在私有 QA 目录。

服务端文本模型使用用户授权的新 OpenAI 兼容接口 `https://api.ai-pixel.online/v1`。模型列表实际提供 `deepseek-v4.1-flash`，不是自行假设一个 `deepseek-v4.1` 别名。ASR 配置独立保留。切换模型后已冻结的旧模型运行不得静默变更模型身份或重放未知扣费请求。

发布脚本验证并记录论文配置哈希、账号有效性和文件权限，与模型配置一起在停止服务后的备份边界切换；回滚恢复旧模型和旧论文配置。客户端 0.3.3 可直接使用此服务端更新，无需因模型或论文工具再换 APK。
