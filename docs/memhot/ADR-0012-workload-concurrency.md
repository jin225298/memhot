# ADR-0012 聊天、翻译、日报与研究的独立并发

日期：2026-10-14；状态：采用；服务端版本：0.3.12。

## 问题与决定

旧实现只有一个全局 Pi 子进程名额。即使 worker 同时领取两个任务，聊天、翻译和研究仍会竞争同一个 Agent；同一用户的所有后台任务还被一条 SQL 排他条件串行化。翻译入口把研究积压也算进翻译待处理数量。增加 worker 数量不能独立解决这些问题。

现在为 Chat、Translation、Digest、Research 各预留一个 Agent 名额和一个模型 HTTP 名额。两层许可分别持有，防止 Agent 等待自己占据的模型许可。名额属于 App，共享于所有 App 克隆；不依赖跨测试进程静态状态。同一用户能同时使用四类功能，同一类仍只允许一个执行或等待请求。聊天所有权覆盖登记请求、读历史、运行 Agent、提交答案的完整区间，保留末端 CAS 防止期间删除或修改上下文。

每类执行名额之外最多容纳 16 个等待者，先到先得，等待 30 秒后返回 busy。重复请求不能占满等待队列。等待发生在付费预留前；正常完成、异常返回和任务取消都会释放许可。供应商请求已发出后取消不能证明没有计费，继续保留原有 unknown 账本，不自动退款或重复付费重试。进程门控只约束本服务在途请求，不能控制供应商收到请求后继续运行的计算。

## 持久任务调度

Translation、Digest、Research 各有一个 worker 循环，另有独立维护循环。Translation 只处理 material_translation；Digest 处理 digest；Research 保留 formation、cognition、daily_summary、research、transcribe 之间的顺序。实时 ASR 仍使用单独的原有容量，不占文本模型名额。

生产 worker 只能使用 `claim_lane`。IMMEDIATE 事务把选择任务、领取 960 秒租约、递增 attempt 和推进用户轮次放在同一事务；跨数据库连接也不能同时领取同一类的两个有效任务。每类独立记录 `scheduler_lane_turns`，重启后继续按用户轮转；新表只在首次迁移时从原 scheduler_turns 初始化。空闲轮询不会消耗排队任务的 attempt。执行仍有 840 秒时限，过期租约、旧 attempt 和删除后的提交继续受到原有验证约束。

`claim()` 保留给测试及管理程序按全局用户轮次取任务，其同类约束是按用户而非全局，不能用于生产并发 worker。两种领取路径共用实现；没有兼容 shim。默认无 Job 的模型调用归 Chat，目前仅用于交互调用；新增后台调用必须携带 Job。

翻译入口只计算当前用户自己的待处理翻译，最多 8 个；研究和日报积压不再阻止提交翻译。已有翻译的重复提交仍返回同一任务，不产生新扣费。

## 资源与可观测性

当前部署是单实例，不声称支持跨主机的全局模型限流。四类各一个执行名额是当前服务器的保守容量，不是无限并行。Pi 子进程的 128 MiB V8 堆上限不等于进程 RSS。系统限额调整为 MemoryHigh=512M、MemoryMax=768M、CPUQuota=150%、TasksMax=128；保留硬上限保护宿主机。

网页插件与 MCP 各自仍保留一个共享子进程名额。因此模型和任务可并行，工具读取仍可能等待；网页处理的 60 秒期限包含其排队时间。本次不声称搜索工具全链路隔离，也没有改成聊天逐字流式输出。日志仅记录 lane、agent/model 阶段和等待毫秒数，不记录用户内容或密钥。

`ops/memhot/sdk-concurrency-smoke.mjs` 使用四个真实 Pi 会话和一个真实网页 worker，以首轮模型请求屏障证明真实重叠。模拟 SSE/网页响应，禁止网络；无需密钥、不调用付费模型。2026-10-14 原安装路径实测四会话全部完成，共 7 次模拟模型 RPC、3 次工具 RPC；cgroup 峰值 437,534,720 bytes（约 417 MiB）、pids 峰值 66，无 high/max/OOM 事件。该结果证明旧 384 MiB / 64 tasks 配额不够，不能代替真实模型的时延测量或最大上下文压力测试。新发布目录重新生成缓存后，同一离线检查峰值 349,347,840 bytes（约 333 MiB）、pids 66，无 high/max/OOM；四路初始化到首个模型帧约 54.8 秒，总计约 65.1 秒。当前主机上冷启动仍明显，不能把并发可完成说成低延迟已解决。

发布时网页编译缓存必须绑定新 SDK 安装路径。即使复制的源码和依赖哈希相同，旧路径的缓存也会退回冷编译。发布验证现在拒绝这种旧凭据复用；本次只硬链接复制已校验的不可变依赖，删除候选目录自己的缓存链接，重新生成缓存并在 Linux 重新验证，旧运行目录保持不变。

## 验证与回滚

Rust 覆盖四类同时运行、等待取消/超时/失败释放、FIFO、重复用户拒绝、讨论 handler 在登记和计费前拒绝重复请求、翻译不受研究积压影响；调度测试覆盖跨连接竞争、租约恢复和旧任务提交、每类用户轮转、重启/一次迁移、幂等与新日报优先。现有账本并发、未知结果保留和多租户隔离测试继续运行。

上线前对数据库备份副本迁移并比较原记录、用户、任务和钱包。暂停入口并排空已接受请求后切换，不中止正在付费的工作。失败使用对应数据库快照、旧 binary/SDK 和旧 systemd 限额回滚；恢复入口。增加的轮次表不更改客户端 API，无需重新安装 APK。

追踪 CONCURRENCY-01：需要更多同类并发或多实例时，先测真实上下文、MCP、ASR 同时工作下的峰值；将执行配额配置化并建立跨实例许可，不能仅扩大 worker 数。

追踪 CONCURRENCY-02：共享网页/MCP 门仍可能影响交互延迟。后续基于工具等待指标引入交互优先或独立工具容量，并在额外子进程的资源实测通过后启用。

追踪 INTERACTION-01：实测多 Pi 冷启动仍慢，需要后续评估隔离常驻工作进程的成本和复用边界；聊天仍等待完整结果，翻译仍用任务状态轮询；端到端流式响应与更及时的前端状态反馈是独立工作，本次并发改造不冒充已完成该体验改造。
